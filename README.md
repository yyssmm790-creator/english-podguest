# Podguest

내 일상을 쉬운 영어로 말해보는 모바일 중심 스튜디오 프로토타입입니다.

## 실행

Node.js 22 이상에서 별도 패키지 설치 없이 실행합니다.

```sh
cd /workspace/english-podguest
npm start
```

기본 포트는 3000이며 `PORT`로 변경합니다. 시작 시 독립 HTML을 빌드합니다. `npm run build`는 빌드만, `npm run check`는 JavaScript 구문 검사, `npm test`는 음성 API 검증을 실행합니다.

## 화면 흐름

- 첫 화면은 스튜디오와 큰 마이크 버튼입니다. 한국어로 이야기하고 마이크를 다시 눌러 마치면 연습 방식 선택으로 넘어갑니다. 글로 남기기와 예시 체험도 가능합니다.
- AI와 대화하기: 움직이는 추상 AI 형태, 큰 질문과 답변 대본을 표시합니다. 가운데 버튼은 ‘시작 / 멈춤’이며 아래 ‘다음 질문’으로 직접 넘길 수도 있습니다. 음성 설정은 ‘목소리’ 안에 접어두었습니다.
- 팟게스트 되어보기: 위에 마이크, 아래에 큰 대본이 표시됩니다.
- 팟게스트의 ‘가리며 말하기’는 큰 스튜디오 마이크를 보여줍니다. 마이크를 눌러 권한을 허용하면 녹음하고, 다시 누르면 마치면서 일기장에 자동 저장합니다. 대화 모드의 ‘대본 가리기’는 대본 표시만 전환하므로 대화 시작·멈춤을 방해하지 않습니다.

사람 사진과 입 애니메이션을 사용하지 않습니다. 대화를 시작할 때 빛·물결·구름 중 한 형태를 무작위로 선택합니다. ‘모습 바꾸기’는 현재와 다른 형태를 선택하고, 질문이 바뀌어도 그 모습은 유지합니다.

## 현재 가능한 체험과 제한

세 가지 예시 이야기(커피·직장·산책)의 영어 대본과 질문을 제공합니다. 질문에는 예시 내용과 감정에 맞는 짧은 추임새를 넣었습니다. 대화 모드에서 시작을 누르면 마이크를 한 번 연결하고 질문 음성이 끝난 뒤 자동으로 답변을 녹음합니다. 실제 말소리가 충분히 감지된 뒤 약 3초간 조용하면 650ms 후 다음 질문을 재생합니다. 짧은 망설임과 발화 전 침묵은 질문을 넘기지 않습니다. 마지막에는 마무리 인사를 하고 마이크를 해제합니다. 멈춤·녹음 재생·화면 이동은 대화를 중단하고 대기 중인 반응을 취소합니다. 시작하면 현재 질문부터 이어집니다. 대화 중 음성 변경은 잠시 잠그며, 모습은 바꿀 수 있습니다. 사용자가 실제로 말한 내용을 의미적으로 이해해 응답하는 기능은 아닙니다. 자유롭게 입력한 이야기는 방식 선택 화면까지 보존하지만, 영어 생성과 실시간 AI 대화는 아직 연결 전이므로 예시 연습을 안내합니다. 예시를 사용자 이야기의 번역이라고 표시하지 않습니다. 발음 평가·영상 촬영·계정·클라우드 동기화는 구현하지 않았습니다.

한국어 음성 입력은 브라우저 Web Speech API를 사용합니다. 브라우저에 따라 원격 음성 인식 서비스를 사용할 수 있습니다. 지원하지 않는 브라우저는 글 입력을 안내합니다. HTTPS 또는 localhost와 마이크 권한이 필요하며, 채팅의 HTML 미리보기에서는 권한이 제한될 수 있습니다.

녹음은 서버에 업로드하지 않습니다. 팟게스트 녹음은 날짜·제목·대본·원래 이야기와 함께 브라우저 IndexedDB에 저장합니다. 일기장에서 제목 수정, 음성 재생, 다운로드와 날짜순 기록을 볼 수 있습니다. 녹음 개수·기록한 날짜 수·총 말한 시간은 연습 기록이며 실력 평가 점수가 아닙니다. 브라우저 저장소를 지우면 사라질 수 있고 다른 기기나 주소와 동기화되지 않습니다. 저장 실패 시 저장됐다고 표시하지 않고, 현재 창의 미저장 녹음을 일기장에서 다운로드하도록 안내합니다. AI 대화의 답변 녹음은 현재 페이지에서만 보관합니다. 답변 녹음은 최대 3분, 자동 대화는 최대 5분이며, 화면을 이동하거나 앱이 배경으로 가면 자동 대화를 중지합니다. AI 대화 녹음은 새로고침 전에 다운로드해야 보관할 수 있습니다. 녹음 중 창을 닫거나 새로고침하면 마지막 녹음은 유실될 수 있으므로 마이크를 눌러 녹음을 먼저 마쳐주세요. 권한 거절 시 다시 시도하거나 대본을 볼 수 있습니다. 상단 ‘카페 음악 연속 듣기’는 사용자 클릭으로만 켜집니다. 자체 제작한 32초 피아노·베이스 연주곡을 반복하며, 대화·음성 입력·녹음·녹음 듣기 중에는 재생 위치를 유지한 채 잠시 음소거합니다. 끄면 재생이 멈추고 다시 켜면 이어서 재생합니다.

## 소스와 미리보기

`public/index.template.html`, `public/style.css`, `public/orb.css`, `public/app.js`, `public/voices.js`, `public/voice-turn.js`를 수정합니다. `public/index.html`은 빌드 결과이며 스타일·스크립트·아이콘·카페 음악을 포함한 단일 파일입니다. 외부 Google Fonts를 사용할 수 없으면 시스템 글꼴을 사용합니다. 다운로드 HTML은 서버의 비밀값을 포함하지 않습니다.

## 영어 목소리

여성 5개(Jenny, Aria, Ava, Emma, Michelle), 남성 4개(Guy, Andrew, Brian, Eric)만 제공합니다. Davis는 재생 불가 보고에 따라 제거했습니다. 기기의 영어 목소리 이름이 정확히 일치하면 로컬 음성을 사용하고, 다른 성별 또는 무작위 목소리로 대체하지 않습니다. 재생 실패·6초 이상 무응답은 안내하고 재시도를 지원합니다.

모든 고정 목소리를 일관되게 사용하려면 Azure Speech 연결이 필요합니다. 키는 환경 설정의 `SPEECH_KEY`에 안전하게 입력하고 `SPEECH_REGION`에 해당 리소스 지역을 지정합니다. 초안의 제안 지역과 비밀값 전달 대상은 `eastus` 및 `eastus.tts.speech.microsoft.com`입니다. 다른 지역의 리소스라면 대상 호스트도 바꿔야 합니다. 키를 코드·HTML·채팅에 넣지 않습니다. 공급자 사용 요금이 발생할 수 있습니다.

`GET /api/voice-status`의 configured는 설정 존재만 뜻하며 실제 인증 성공을 보장하지 않습니다. `POST /api/speech`는 허용 음성·요청 크기·출처를 확인하고 SSML을 이스케이프한 뒤 음성을 요청합니다. 현재 환경에는 연결 키가 없어 실제 Azure 음성은 미검증입니다. 공개 배포 전에는 사용자 인증과 사용량 제한이 필요합니다.

## 검증

음성 API의 3개 테스트는 고정 목소리 목록, 설정 누락, 요청 검증, SSML 이스케이프와 공급자 실패 처리를 모의 공급자로 확인합니다. 모바일 화면과 실제 녹음 경로는 Chromium의 모의 마이크로 검증합니다. 음성 입력의 화면 전환은 모의 음성 인식 이벤트로 검증하며 실제 한국어 인식 정확도를 보장하지 않습니다. 작업 공간의 실행 Chromium은 관리자 정책으로 file:// 열기를 차단하므로, 다운로드 파일을 브라우저에서 직접 연 상태의 마이크 권한은 여기서 검증할 수 없습니다.

## AI 형태의 움직임

녹음 중에는 Web Audio AnalyserNode로 마이크 입력의 RMS 크기를 측정해 형태의 크기와 빛에 반영합니다. 마이크는 스피커에 연결하지 않으며 별도 서버로 전송하지 않습니다. 녹음 중지·화면 이동 시 분석 노드와 animation frame을 해제합니다. 연결 대기·듣기·응답 대기·실제 음성 재생 상태를 글자로 함께 표시합니다. 브라우저 음성 합성의 출력 파형은 직접 분석할 수 없어, AI 발화 움직임은 실제 재생 시작·종료 이벤트에 맞춘 시각 효과입니다. 음소별 동기화는 아닙니다. 음성 재생이 불가능하면 말하기 상태를 꾸며서 표시하지 않습니다. ‘움직임 줄이기’ 접근성 설정을 존중합니다.

Chromium의 모의 마이크와 음성 엔진으로 세 가지 형태 전환, 형태 유지, 입력 크기 반응, 상태 전환, 예시 추임새, 자동 다음 질문·마무리, 재생·이동 시 예약 반응 취소, 권한 거절, 움직임 줄이기, 세 가지 휴대폰 폭 및 독립 HTML을 검증했습니다. 실제 대화 이해나 전용 음성 공급자의 인증·음질을 검증한 것은 아닙니다.

## 시작 / 멈춤 대화

`VoiceTurnDetector`는 기기에서 측정한 음량과 침묵 시간으로 답변이 끝난 시점을 추정합니다. 음성 인식이나 의미 이해는 아니며 조용한 목소리·주변 소음에 따라 직접 ‘다음 질문’을 눌러야 할 수 있습니다. 질문을 재생하는 동안은 사용자 답변을 녹음하지 않고, 끝난 뒤 350ms를 기다려 듣습니다. 한 세션의 마이크를 재사용해 질문마다 권한을 요청하지 않습니다. 멈춤·종료·권한 취소·음성 재생 실패 시 음성 작업, 타이머, 분석 노드, 마이크 트랙을 해제합니다. 사용자가 마이크 허용을 기다리다 멈춘 경우 나중에 도착한 마이크도 즉시 해제합니다.

`npm test`는 음성 API 3개와 발화 종료 감지 4개, 총 7개 테스트입니다. 발화 전 침묵, 짧은 망설임, 단발성 잡음, 한 번만 종료하는 조건과 초기화를 검증합니다. 브라우저에서는 제어 가능한 로컬 오디오 스트림과 모의 음성 엔진으로 시작 한 번 → 질문 → 듣기 → 침묵 후 다음 질문, 마이크 재사용, 질문 도중 직접 넘기기, 시작/멈춤/이어가기, 마지막 인사 후 종료, 권한 거절·대기 취소, 재생 실패, 팟게스트 녹음을 검증했습니다. 실제 마이크 환경의 정확도나 공급자 음성 인증을 검증한 것은 아닙니다.

## 상단과 시작/멈춤 상태

상단은 “I'm an English Podguest. / 나는 영어 팟게스트”로 표시합니다. `public/audio/cafe-original.mp3`는 이 프로젝트를 위해 새로 합성한 피아노·베이스 연주곡이며, 기존 상업 음원을 사용하지 않습니다. 빌드 시 음악을 HTML에 포함해 외부 음악 서버 없이 재생합니다.

시작 버튼은 초록색, 실행 중 멈춤 버튼은 붉은 갈색이며 색 전환 지연을 없앴습니다. 버튼의 아이콘·문구 노드를 매번 교체하지 않아 누르는 도중 상태 갱신이 있어도 터치를 유지합니다. 실행 상태는 `aria-pressed`로도 전달합니다. 브라우저에서 UI 갱신 중 터치, 발화 중·녹음 중·권한 대기 중·응답 준비 중 멈춤과 색 복구, 마이크 해제, 음악의 실제 재생·루프·켜기/끄기·오프라인 재생, 네 가지 화면 폭을 검증했습니다.

팟게스트 일기장은 Chromium 모의 마이크로 대본 가리기 후 녹음 대기 → 마이크로 시작·종료 → 자동 저장 → 제목 수정 → 새로고침 후 제목·음성 유지 → 실제 오디오 재생과 모바일 가로 넘침 없음을 검증했습니다.

대화하기 최신 흐름: 시작 버튼은 대화 연결만 수행하며 연결 중과 말하는 중에는 비활성화됩니다. 멈춤 토글은 제거했습니다. 침묵에 따른 자동 질문 전환도 제거했고, ‘다음 질문’을 누를 때 현재 답변 녹음을 종료한 뒤 다음 질문을 읽고 다시 듣습니다. 화면 이동·마이크 오류·시간 제한 시 마이크를 해제하는 보호 동작은 유지합니다. Chromium 모의 마이크로 시작, 질문 자동 전환 없음, 수동 다음 질문 후 재녹음, 화면 이동 시 해제를 검증했습니다. 위의 자동 질문 전환 설명은 이전 버전의 동작입니다.

팟게스트 시작 버튼은 ‘시작하기’로 표시합니다. 팟게스트에서도 실제 마이크 입력의 RMS로 큰 마이크 크기와 입력 막대를 갱신하며, 녹음 시 경과 시간을 표시합니다. 침묵에는 입력 반응이 줄어들고 녹음을 마치면 분석을 해제합니다. 미리보기의 마이크 Permissions Policy 차단, API 미지원, 권한 거절은 화면 안내로 표시하며 녹음 중이라고 꾸미지 않습니다. Chromium의 제어된 로컬 오디오 스트림으로 음량 반응/침묵/타이머/자동 저장/마이크 해제/권한 거절 후 재시도를 검증했습니다. 채팅 미리보기 자체의 마이크 권한은 이 테스트로 보장하지 않습니다.

대본을 보며 팟게스트 녹음을 시작하면 버튼 색이 바뀌고 영어 SpeechRecognition 결과를 대본의 단어 순서와 비교하여 문장 단위로 강조/스크롤합니다. 녹음 시간에 따라 대본이 자동으로 넘어가지는 않습니다. 영어 인식은 브라우저 제공 기능으로 네트워크/서비스 지원이 필요할 수 있으며 브라우저 공급자에게 음성이 전송될 수 있습니다. 녹음 파일 자체는 앱 서버로 업로드하지 않습니다. 인식 미지원/연결 오류/종료 시 대본 따라가기 제한을 표시하며 녹음은 독립적으로 계속됩니다. 대본을 가리거나 녹음을 끝내거나 화면을 이동하면 인식을 해제합니다. 대본 유무와 관계없이 녹음 중 연결 상태와 실제 RMS 기준 목소리 감지 상태를 표시하고 녹음 시간을 갱신합니다. 제어된 Chromium 오디오와 모의 영어 인식 이벤트로 문장 강조/이동, 가리기 시 인식 해제, 입력 반응/시간/저장을 검증했습니다. 실제 영어 인식 정확도와 채팅 미리보기 권한은 검증하지 않았습니다.

카페 음악 최신 변경: 자체 제작 MP3 대신 사용자가 제공한 YouTube 영상 Fe4LW27f_A0을 공식 IFrame Player API로 삽입했습니다. 상단 음악 버튼으로 보이는 재생창을 열고 닫으며, 사용자 클릭 전에는 YouTube 스크립트를 요청하지 않습니다. 플레이어 실제 상태 이벤트로 ON 표시, 녹음/말하기 중 음소거, 닫을 때 일시정지를 연결했습니다. YouTube 자동 믹스 RDFe4LW27f_A0은 고정 10곡 목록이 아니므로 임의로 10곡을 만들거나 보장하지 않습니다. 원래 믹스 링크를 재생창에 제공합니다. 외부 접속이 제한된 작업 환경에서는 실제 영상의 재생 가능 여부·제목·재생목록을 확인할 수 없었습니다. 모의 YouTube API로 재생/닫기/음소거 복구와 접속 차단 시 원래 링크 안내를 검증했습니다. 음악은 이제 인터넷 연결이 필요하며 자동 재생 또는 삽입이 차단되면 재생창의 재생 버튼이나 원래 링크를 이용합니다. 앞의 로컬 MP3·오프라인 음악 설명은 이전 버전입니다.

배포 준비 최신 상태: YouTube 삽입을 제거하고 기존 자체 제작 cafe-original.mp3를 HTML에 내장해 사이트 내부에서 직접 재생하도록 복구했습니다. 사용자가 제공한 YouTube 음원이나 10곡이 아닙니다. 사용자 클릭 후 실제 재생 성공 시 ON으로 표시하고 음성 활동 중 음소거합니다. Chromium에서 실제 내장 MP3 재생/음소거/복구/중지를 확인했습니다. netlify.toml은 public 폴더 정적 배포를 설정하며 Azure API 서버를 배포하지 않으므로 이 경로의 음성은 사용 가능한 기기 음성을 이용합니다. HTTPS 사이트에서 마이크 권한을 허용해야 합니다. 별도 호스팅 연결/로그인 없이 공개 주소를 발급하지 않았습니다. 정적 사이트는 예시 연습 체험판이며 자유 이야기 AI 변환은 미연결 상태입니다. 일기장은 브라우저·출처별 저장이므로 미리보기 기록은 새 배포 주소로 자동 이전되지 않습니다.

최근 대화 UX: 사용자 요청에 따라 자동 질문 연결을 다시 활성화했습니다. 시작은 연결만 수행하며 멈춤 토글은 없습니다. 실제 마이크 말소리가 감지된 뒤 약 3초의 침묵을 기다리고 다음 예시 질문으로 이어갑니다. 수동 ‘다음 질문’도 유지합니다. 버튼 위 9개 막대는 실제 마이크 샘플 구간별 RMS에 반응하며, 침묵에는 줄어듭니다. 음성이 감지되면 ‘목소리가 들려요’, 조용하면 ‘듣고 있어요 · 편하게 말해주세요’를 표시합니다. 이는 의미 이해가 아닌 발화 종료 감지로, 자유 응답 AI는 아직 미연결입니다.

최근 음악 교체: 기존 피아노 음원을 새로 합성한 약 47초 어쿠스틱 기타 스타일 핑거피킹 cafe-acoustic.mp3로 바꿨습니다. scripts/generate_acoustic.py로 재생성할 수 있으며 재생성에만 NumPy/SciPy/ffmpeg가 필요합니다. 배포/빌드는 저장소의 MP3 파일을 사용하므로 Python 의존성 설치가 필요하지 않습니다. 유튜브 음악이나 실제 연주 녹음이 아닌 자체 생성 반주입니다.

팟게스트 최신 분리: 대본이 보이는 동안 ‘시작하기’는 마이크 분석과 영어 SpeechRecognition만 시작합니다. MediaRecorder를 만들지 않으며 녹음 파일/일기장 항목을 저장하지 않습니다. 대본의 각 단어를 span으로 표시하고 누적 인식 결과를 대본 순서와 비교해 단어 블록을 이동합니다. 발음 판정이 아니며 브라우저 인식 지연/오인식이 있을 수 있습니다. 가리기 전 읽기 인식과 마이크를 종료하고, 가린 화면에서 큰 마이크를 눌렀을 때만 팟게스트 녹음/저장을 수행합니다. 대본을 다시 열면 녹음을 마치고 읽기 연습 대기로 돌아갑니다. 읽기 중에는 대화 모드와 같은 말하는 중 버튼/실제 목소리 파형만 표시하고 녹음 시간/녹음 중 표시는 하지 않습니다. 인식 미지원/오류/종료 시 재시도를 안내하고 읽기 마이크를 해제합니다. 단어 정렬 테스트 3개를 추가해 총 10개 Node 테스트가 통과했으며, Chromium 모의 음성 인식/실제 로컬 오디오로 읽기 시 MediaRecorder 생성/일기장 저장 없음, 단어별 이동, 가리기 시 마이크 해제, 가린 녹음만 저장, 인식 오류 후 재시도와 모바일 가로 넘침 없음을 확인했습니다.
