# 내 이야기 AI 연결 (Netlify)

코드는 API 키 없이 빌드/배포됩니다. 실제 생성에는 OpenAI API 키와 사용 가능한 API 크레딧이 필요합니다. ChatGPT 구독과 API 요금은 별개입니다.

## Netlify에서 설정

1. `my-english-podguest` 프로젝트의 **Project configuration → Environment variables**를 엽니다.
2. **Add a variable**에서 다음 항목을 저장합니다.
   - Key: `PODGUEST_AI_KEY`
   - Value: 본인의 OpenAI API 키. 채팅이나 GitHub에 붙여넣지 않습니다.
   - Scope를 고를 수 있다면 **Functions**에 적용하고 Production 배포에 값을 설정합니다.
3. 기본 모델은 `gpt-4.1-mini`입니다. 다른 구조화 출력 지원 모델을 쓰려면 선택적으로 `PODGUEST_AI_MODEL`을 설정합니다.
4. **Deploys → Trigger deploy**에서 최신 브랜치를 다시 배포합니다. 환경변수 변경은 새 함수 배포에 반영되어야 합니다.
5. **Published** 후 사이트를 새로고침합니다. 예시가 아닌 짧은 일상을 입력하고 ‘내 이야기로 영어 만들기’를 누릅니다.
6. 1·2·3단계를 바꾸어 대화문과 팟게스트 대본을 확인합니다. 같은 입력의 단계 변경은 그 화면에서는 추가 API 요청을 하지 않습니다.

키를 설정하기 전에는 예시 이야기는 작동하지만 자유 입력의 실제 생성은 `ai_not_configured` 안내가 나옵니다. 브라우저에 키를 입력하는 UI나 공개 API 키는 없습니다.

## 동작

- 한국어 음성 입력은 브라우저 음성 인식이 글로 변환합니다. 이 앱의 대본 API에는 글만 전송합니다. 브라우저 음성 인식 서비스의 처리 방식은 해당 브라우저 정책을 따릅니다.
- `POST /api/story`에 `{ "story": "내 이야기" }`를 보냅니다. 입력은 최대 2,000자입니다.
- Netlify의 `netlify/functions/story.mjs`가 `lib/story-service.js`를 호출합니다. 로컬 Node 서버도 같은 서비스를 사용합니다.
- 앱 서버가 OpenAI Chat Completions API에 3단계의 팟게스트/대화문을 엄격한 JSON 구조로 요청합니다. `store:false`이며 앱 서버에는 이야기를 파일/DB로 저장하지 않습니다. API 공급자의 데이터 정책은 별도입니다.
- 결과를 검증한 후 브라우저에 전달합니다. 잘못되거나 잘린 결과를 예시 대본으로 바꿔서 성공했다고 표시하지 않습니다.
- 1단계: A1의 아주 짧은 문장. 2단계: A2의 자연스러운 일상 표현. 3단계: B1의 조금 더 풍부한 표현. 단계가 바뀌어도 사실을 추가하지 않도록 지시합니다.
- 대화는 내 이야기를 바탕으로 생성한 질문/예시 답변을 연습합니다. 이후 마이크 답변의 의미를 AI가 매번 해석해 새 질문을 만드는 실시간 챗봇은 아닙니다.
- 취소/오류 시 원래 입력을 유지합니다. 작성 중인 글과 현재 3단계 대본은 해당 브라우저 localStorage에서 이어 연습할 수 있도록 기억합니다. 마지막 연습 대본/표시 상태도 복원하며, 새 생성 결과를 일기장이나 대본 목록에 자동 추가하지 않습니다. 목록 삭제와 저장 실패 안내를 제공합니다. 계정/기기간 동기화는 없고 브라우저 데이터 삭제 시 사라집니다.
- 대본을 가리고 큰 마이크로 녹음한 뒤 사용자가 💾를 눌러 선택한 경우에만 원래 이야기, 생성 대본, 제목, 단계와 음성을 브라우저 IndexedDB 일기장에 한 세트로 저장합니다. 대본 보며 연습/녹음 종료/홈 이동/웹 닫기는 일기장에 음성을 저장하지 않습니다. 연습 직후 듣기는 메모리의 Blob을 재생하며, 미저장 음성은 창을 닫으면 사라집니다.

## 비용/공개 운영

- 한 번의 생성으로 3단계를 함께 받습니다. API 사용료는 계정에 청구됩니다. OpenAI 프로젝트의 예산/사용량 설정을 함께 확인하세요.
- 길이/시간 제한, 같은 출처 검사와 IP 기반 제한을 넣었습니다. 제한은 실행 중인 함수 인스턴스마다 10분에 6번으로 동작하는 best-effort 제한이며 분산 환경의 전역 예산 한도가 아닙니다. 공개 사용량이 늘면 인증/중앙 제한이 필요합니다.
- 공급자 오류 메시지, 키, 원래 이야기를 서버 로그에 출력하지 않습니다. `GET /api/story`는 설정 유무만 반환합니다.

## 로컬 실행

Node.js 22 이상에서 환경변수를 주입하거나, `.env.example`을 복사한 `.env`를 사용합니다. `.env`는 Git에서 제외합니다.

```sh
npm run build
node --env-file=.env server.js
```

`npm start`는 이미 프로세스에 설정된 환경변수를 사용하며 `.env`를 자동으로 읽지 않습니다. `npm test`는 실제 유료 요청 없이 모의 공급자로 검증합니다.

## 이번 검증 범위

- Node 테스트 16개 통과: 입력/출처/출력 검증, 세 단계 요청, 설정 없음, 공급자 오류/시간 초과/거절, 호출 제한, Netlify 어댑터 등.
- Chromium의 iPhone 화면 설정: 자유 입력 → API 결과 → 단계 전환, 대화문/혼자 읽는 대본 분리, 말하기 시작/종료, 음성 입력의 글 전달, 취소/실패 시 보존, 녹음 일기장의 제목·원문·단계, 모바일 가로 넘침 없음.
- AI 공급자는 테스트 응답으로 대체했습니다. 실제 API 키가 실행 환경에 없으므로 유료 모델의 실제 문장 품질/생성 지연과 배포된 Netlify 함수의 실제 공급자 연결은 아직 검증하지 않았습니다. 키 설정 후 실제 이야기로 확인해야 합니다.

## 녹음 종료와 이야기 저장 검증

- 녹음은 브라우저가 지원하는 Opus/WebM 또는 MP4로 요청하고, 1초 간격의 데이터 조각을 하나의 파일로 합칩니다. 이는 곡이나 녹음을 1초마다 재시작하는 동작이 아닙니다.
- 마지막 dataavailable와 stop 이벤트가 끝난 뒤 마이크 트랙을 해제합니다. 종료 처리 중에는 재녹음을 잠시 막습니다.
- Chromium 실제 MediaRecorder + 제어된 연속 음원으로 여러 조각을 녹음하고, 저장한 Blob을 다시 디코딩하여 중간 무음 구간 없음과 최종 데이터 수신 후 트랙 종료를 확인했습니다. 실제 노트북 마이크 및 iPhone Safari의 음질을 검증한 것은 아닙니다.
- 브라우저 시나리오: 초안 새로고침 복원, 복수 이야기와 생성 대본 복원(추가 API 요청 없음), 목록 삭제 후 새로고침, 저장 공간 오류 안내, 5개 모바일 너비 검증.

브라우저 회귀 검사는 로컬 서버를 켠 뒤 Playwright 설치 환경에서 `node tests/recording-storage.browser.mjs`로 실행합니다. 필요하면 `BASE_URL`, `CHROMIUM_PATH`, `PLAYWRIGHT_MODULE` 환경 변수로 서버 주소, 브라우저, 모듈 경로를 지정합니다. API 응답은 모의 데이터이며 실제 AI 비용은 발생하지 않습니다.

## 공통 AI 음성 — 2026-10-22

- 같은 `PODGUEST_AI_KEY`로 OpenAI `gpt-4o-mini-tts` 음성을 생성합니다. 추가 Azure 계정이나 별도 키는 필요하지 않습니다. Netlify 재배포 시 speech/voice-status 함수와 두 경로가 함께 배포됩니다. 새 음성 생성에는 OpenAI API 사용료가 발생합니다.
- 기본 Nova, 추가 Shimmer/Onyx/Echo를 고정 카탈로그로 제공합니다. iPhone과 컴퓨터 모두 같은 음성을 요청하며 기기별 브라우저 음성 목록/합성은 사용하지 않습니다. 연결 실패 시 다른 목소리로 바꾸지 않습니다. 설정에 AI 생성 음성임을 표시합니다.
- 읽을 영어 문장과 선택한 음성 ID가 서버를 거쳐 OpenAI로 전송됩니다. 사용자 마이크 녹음은 이 음성 API에 올리지 않습니다. 키나 공급자의 원본 오류는 반환하지 않습니다.
- MP3 바이너리를 Netlify base64 응답으로 반환합니다. 브라우저는 같은 오디오 요소를 사용하며, 최초 클릭에서 짧은 무음 WAV로 재생을 준비합니다. 이는 Safari 자동 재생 정책을 고려한 처리이며 실제 기기 검증이 필요합니다.
- 같은 목소리/문장의 결과는 현재 페이지에서만 최대 16개/10MB 캐시합니다. 저장 응답은 no-store이며 사이트 서버에 개인 대본이나 생성 음성 파일을 보관하지 않습니다. 공급자의 데이터 정책은 별도입니다.
- 요청당 3,000자/16KB, 25초 공급자 제한, 입력 ID 검증, 동일 출처 확인, warm instance당 IP 기준 40회/10분 제한이 있습니다. 이 제한은 인스턴스를 넘는 전역 비용 상한은 아닙니다.
- Node 검사: 입력/출처/모델·음성 전달, API/오디오 오류, 요청 제한, Netlify 바이너리 보존. 브라우저 검사: 서로 다른 기기 음성 목록을 사용하지 않는지, 고정 카탈로그, 실제 WAV 재생과 재사용, 오류 복구, 대화 중 일시정지·이어하기. 공급자는 모의 응답이며 실제 OpenAI 음질/계정 권한은 배포 후 확인해야 합니다.

## 선택 저장과 중단한 대본 복원

- 대본 표시: 작은 상단 마이크 + 🔊/🗣️/↻. 대본 가리기: 기존 큰 마이크 + 🗣️/💾/↻.
- 🗣️는 진행 중 녹음을 마친 후 바로 듣게 하고, 💾는 최종 음성 데이터를 받은 뒤 고유 take ID로 한 세트를 저장합니다. 중복 클릭은 같은 녹음을 복제하지 않습니다. 저장 오류 시 음성을 메모리에 유지하고 다시 저장할 수 있습니다.
- ↻는 새 일기장 항목을 만들지 않고 현재 연습 음성을 버립니다. 화면 모드 전환도 녹음을 마치며 이전 단계의 음성을 가린 녹음으로 잘못 저장하지 않습니다.
- `podguest-current-practice-v1`은 마지막 대본/단계/가리기 상태만 localStorage에 보관합니다. 마이크 음성을 자동 저장하지 않습니다. 더 최근에 작성한 입력 초안이 있으면 오래된 연습 대본이 덮어쓰지 않습니다. 이전 일기장 데이터는 삭제하거나 변환하지 않습니다.
